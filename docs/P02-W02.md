# P02-W02 — Quick Expense

## Scope

Quick Expense is a simple operational expense-entry doctype for daily business
expenses (transport, loading/unloading, workers, fuel, maintenance, electricity,
other). The operational user fills business fields only; ERPNext accounting
complexity stays hidden. All accounting lives in a standard ERPNext Journal Entry;
the custom app creates no GL entries, ledgers, or duplicated balances. Frappe and
ERPNext core are unmodified.

## Why Journal Entry

For an immediate cash/bank expense there is no supplier invoice or payable, so
Purchase Invoice / Payment Entry do not model the flow. ERPNext's standard document
for a direct two-line cash/bank accounting entry is the Journal Entry (this is
exactly how ERPNext records bank charges, write-offs, and direct expense postings).
The app builds a standard two-row Journal Entry:

- Debit: selected expense account (Expense Category)
- Credit: selected Cash/Bank account (Payment Account)
- amount = Quick Expense amount, posting_date = Quick Expense posting date
- `user_remark` includes the Quick Expense name (and description)
- every JE Account row carries `reference_type = "Quick Expense"` +
  `reference_name` backlink
- `cheque_no` / `cheque_date` map from the optional Reference No / Reference Date

## Journal Entry Account.reference_type extension

ERPNext v15 restricts `Journal Entry Account.reference_type` to a fixed Select list
of standard doctypes. The app-owned Property Setter (`setup.py`,
`_ensure_journal_entry_account_reference_type`) appends `Quick Expense` to that
list, keeping all stock options intact. It is idempotent, owned by the Cardboard
Management module, removed when the app's customizations are removed, and re-ensured
by the existing after_install / after_migrate hooks. ERPNext source files are not
touched.

## Doctype

`Quick Expense` (submittable, autoname `QE-.YYYY.-.#####`, System Manager role like
the rest of the app):

- posting_date (Date, required, default Today)
- company (Link Company, required; auto-derived from the selected accounts when
  omitted)
- expense_account (Link Account, labeled "Expense Category", required)
- amount (Currency, required, non-negative, must be > 0)
- payment_account (Link Account, required)
- payment_mode (Data, optional), supplier_or_party (Data, optional free-text label;
  no Supplier link because there is no payable to allocate)
- description (Small Text), attachment (Attach)
- reference_no (Data), reference_date (Date; requires reference_no)
- accounting_document (Link Journal Entry, read-only, no_copy)
- accounting_status (Data, read-only, no_copy): Not Integrated / Integrated /
  Cancelled — refreshed in `validate` and `onload` from the linked JE docstatus

Account pickers are narrowed in the UI with the native `link_filters` field
attribute (verified in this Frappe version, used by ERPNext v15 doctypes):

- Expense Category: company = doc.company, root_type = Expense, is_group = 0
- Payment Account: company = doc.company, account_type in (Cash, Bank),
  is_group = 0

The server re-validates everything authoritatively (UI filters are UX only):
positive amount; expense account must be enabled, non-group, root_type Expense,
belong to the company; payment account must be enabled, non-group, Cash/Bank type,
belong to the company; both must match the company currency (multi-currency
expenses are rejected rather than partially supported).

## Lifecycle

- Draft save: validations only; no accounting document. Status "Not Integrated".
- Submit (`on_submit` → `create_journal_entry`):
  - row-locked (`select ... for update`) to make concurrent submits safe
  - idempotent: reuses a valid existing linkage by forward link OR by looking up
    `Journal Entry Account.reference_name = this Quick Expense`; a draft JE is
    completed (mapped and submitted), a submitted JE is verified and relinked; a
    cancelled JE raises "a duplicate will not be created"
  - inserts and submits the standard JE, validates the mapping (exact accounts and
    amount both directions), stores the backlink with `db_set`
- Cancel (`before_cancel`):
  - sets `ignore_linked_doctypes` (the same standard tuple ERPNext's own
    Journal Entry / Payment Entry controllers set in `on_cancel`) so the JE's GL
    entries do not block the operational document's cancellation
  - cancels the linked JE first (JE.on_cancel reverses GL fully) with
    `ignore_linked_doctypes = ("Quick Expense",)` on the JE instance so the intact
    forward link is allowed during that ordering
  - refuses to cancel a JE whose rows reference a different Quick Expense
  - status shows "Cancelled" afterwards

## Categories

No expense categories were created — the Chart of Accounts is untouched. Users
select the company's existing expense accounts as categories. Safe pre-seeded
categories were deferred to a future work package with an explicit migration
strategy.
