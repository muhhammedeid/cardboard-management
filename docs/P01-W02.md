# P01-W02 — Discounted Weight and Scale Capture Readiness

## Weight semantics

`net_weight` is the physical weight and is always `gross_weight - tare_weight`.
It is never reduced by a supplier discount. `discount_weight` is derived from
No Discount, Kg, or Percentage input. `payable_weight` is the valuation basis:

```text
discount_weight = 0                                      (No Discount)
discount_weight = discount_value                         (Kg)
discount_weight = net_weight * discount_value / 100      (Percentage)
payable_weight  = net_weight - discount_weight
total_amount    = payable_weight * rate_per_kg
```

The server overwrites all four derived values during validation. Client
calculations are form feedback only. Submission still creates no Purchase
Invoice, Purchase Receipt, Stock Ledger Entry, GL Entry, or payment.

## ScaleReader extension point

No hardware communication is implemented. Draft Cardboard Supply forms expose
**Capture Gross Weight** and **Capture Tare Weight** actions. Until an adapter is
registered, they report that scale integration is not configured.

A future integration registers a device-neutral adapter at
`cardboard_management.scale_reader` with this asynchronous interface:

```javascript
cardboard_management.scale_reader = {
  async read_weight({ frm, target_field }) {
    // Return one numeric weight normalized to Kg.
  },
};
```

`target_field` is either `gross_weight` or `tare_weight`. The adapter should call
a separate ScaleReader/scale gateway service responsible for authentication,
device configuration, serial/TCP protocols, retries, and normalization to Kg.
None of those details belong in the DocType or its client script. A captured
value is still revalidated and all derived values are recalculated on the
server when the document is saved or submitted.
